# New Vlog Import (Raycast Extension)

`newvlog.sh` のロジックをそのまま Raycast 拡張機能にしたものです。
撮影デバイス (Osmo Action / DJI Mic) の素材を、撮影日ごとに SSD のプロジェクトフォルダへ取り込みます。

## 処理の流れ (スクリプトと同じ)

1. **SSD 確認** — `diskutil info <UUID>` でマウントポイントを特定し、`001 Camera/Footage/.import_history` を読み込む
2. **デバイス検出** — `/Volumes` 直下のボリュームから `DCIM/DJI_001` (Osmo Action) / `DJI_Audio_001` (DJI Mic, 最大2台) を検出
3. **ファイルスキャン** — 履歴済み・`*.LRF`・日付不明のファイルを除外し、日付切り替え時刻 (既定 04:00) を考慮した撮影日でグループ化
4. **プラン入力 (Raycast の画面)** — 日付ごとに「既存プロジェクトを使用 / 新規プロジェクトを作成 (タイトル + Tier) / スキップ」を選択
5. **容量チェック** — デバイスごとに「転送予定 + 安全マージン」が空き容量を超える場合は確認ダイアログ (中止 / このまま転送)。転送はバックグラウンドで行うため、前のデバイスの転送で減る分も見込んで**開始前に**まとめて確認する
6. **フォルダ準備** — 新規の場合は Tier フォルダ作成 → `YYYY-MM-DD-タイトル` (重複時は `-1`, `-2`…) → `_Template` をコピー → `_Assets` へのシンボリックリンク `Assets` を作成
7. **転送** — 1ファイルずつ `rsync -a` で転送し、成功したものだけ履歴に追記。完了した日付のプロジェクトフォルダを Finder で開く
8. **結果表示** — 失敗ファイルの一覧、ログ (Support フォルダ内 `logs/` にも保存)。完了すると macOS の通知が届く

## バックグラウンド転送の仕組み

6〜7 (フォルダ準備・転送) は Raycast から切り離したワーカープロセスで実行するので、**転送中に Raycast を閉じても転送は続きます**。

- 終了時 (完了・中断とも) に、ログ `logs/newvlog-*.log` と並べて履歴画面用の要約 `logs/newvlog-*.json` を書く
- ワーカーは `src/worker.ts` を esbuild でバンドルした `assets/worker.js`。Raycast 同梱の node で `detached` 起動する
- 進捗は Support フォルダ内 `job/state.json` に書かれ、画面はそれを読んで表示する (コマンドを開き直すと進捗画面に戻る)
- 起動は Support フォルダ内 `job.lock` のカーネルロック (`O_EXLOCK`) の中で行い、同時に起動されてもワーカーは 1 つだけになる。ロックは保持プロセスが死ねば OS が解放する
- 中止は画面からワーカーに SIGTERM を送る。転送中は `caffeinate` でスリープを防ぐ
- ワーカーが強制終了などで消えた場合は「中断」として表示する。成功したファイルは履歴に記録済みなので、再実行すれば未転送分だけが対象になる

## セットアップ

```bash
cd raycast-newvlog
npm install
npm run dev
```

`npm run dev` (= ワーカーのバンドル + `ray develop`) を一度実行すると Raycast に拡張機能が登録されます。
`npm run build` でも Raycast に登録されます。`src/worker.ts` 側 (転送エンジン含む) を変更したときは `npm run build:worker` か `npm run build` を実行してください (`ray develop` の監視対象外です)。
その後 Raycast で **Import Vlog Footage** を検索して起動してください。

初回起動時は設定画面が開くので、保存先の SSD を選んでください (「001 Camera/Footage」があるボリュームが候補として上に出ます)。

## コマンド

| コマンド | 種類 | 内容 |
| --- | --- | --- |
| **Import Vlog Footage** | 画面 | スキャン → 転送プラン → 転送 / 進捗表示 |
| **Vlog Transfer Status** | メニューバー | 転送中は進捗 %・速度・残り時間・日付ごとの状態、終了後は結果 (中止・フォルダを開く・結果を閉じる)。転送していないときは控えめなアイコンで、前回の取り込み・取り込み開始・履歴・設定への入り口を表示。Raycast の設定でこのコマンドを一度有効にしてください (10 秒ごと + メニューを開いたときに更新) |
| **Vlog Import History** | 画面 | 過去の取り込み (プロジェクト・ファイル数・速度・失敗) を月ごとに一覧 |
| **Configure Vlog Import** | 画面 | 設定フォーム |

### 設定

Support フォルダの `settings.json` に保存されます (Raycast の Preferences は使いません)。

| 項目 | 既定値 | スクリプトの対応箇所 |
| --- | --- | --- |
| 保存先SSD | (必須・マウント中のボリュームから選択) | `SSD_UUID` |
| 安全マージン (GB) | `2` | `SPACE_MARGIN_GB` |
| 日付の切り替え時刻 | `04:00` | `CUTOFF_TIME` |
| 除外するファイル | `*.LRF` | `EXCLUDE_PATTERNS` |
| 既定のタイトル | `NewProject` | `DEFAULT_TITLE` |
| 既定の Tier | Store (`TIER_2__STORE`) | — |
| 日付ごとの転送後にフォルダを開く | ON | `open "$TARGET_PROJECT_DIR"` |
| 転送が終わったら通知する | ON | — |

パスやデバイス検出ルール、Tier 定義は `src/lib/config.ts` にあります。

## 画面操作

### 転送プラン画面

- スキャン直後、日付ごとの転送先は自動で入ります: 既存プロジェクトが 1 つならそれ、無ければ既定のタイトル・Tier で新規作成。既存が 2 つ以上ある日付だけ「未決定」になります
- 同じ撮影日に複数デバイス (Osmo Action と DJI Mic など) の素材があるときは、同じプロジェクトに入ります。1 つの日付の転送先を変えると、同じ日付で未決定のもの・同じ転送先を共有していたものにも反映されます (スキップはその日付だけ)。同じ Tier・日付・タイトルの新規プロジェクトは 1 回の転送で 1 つだけ作られます
- 日付を選んで **Enter** で転送先を選ぶ画面 (既存プロジェクト / 新規作成 / スキップ)
  - **新規プロジェクトを作成** (`⌘N`)、**スキップ** (`⌃X`)、**自動の選択に戻す** (`⌘Z`)
- 右側に転送先・ファイルの種類と数・撮影時刻の範囲・既存プロジェクトを表示
- 先頭の「転送を開始」行に合計と空き容量。**転送を開始** (`⌘↩`) — 容量が足りないときは同じ確認ダイアログの中で警告します
- **再スキャン** (`⌘R`)、**設定** (`⌘⇧,`)

### 転送中 / 結果画面

- 全体の進捗 %・速度・残り時間・経過時間・転送中のファイル、日付ごとの進捗を表示
- **ログを表示** (`⌘L`)、**転送を中止** (`⌘⇧.`)
- 転送を始めると画面ごと進捗表示に切り替わります (Esc で古いプランに戻らない)。Raycast を閉じても転送は続き、メニューバーで状況を見られます
- 完了後: **プロジェクトフォルダを開く** (`⌘O`)、**ログをコピー**、**ログファイルを表示**、**新しいスキャンを開始** (`⌘R`)

## 注意

- 転送中に Raycast を閉じても問題ありません。Mac の再起動やワーカーの強制終了で止まった場合も、履歴は成功したファイルごとに追記されているため、再実行すれば未転送分だけが再度対象になります (スクリプトを Ctrl+C した場合と同じ挙動)。
- `ray lint` は `package.json` の `author` を Raycast Store のユーザー名として検証します。ローカル利用のみなら無視して構いません (`ray build` / `ray develop` には影響しません)。ストアに公開する場合は自分の Raycast ユーザー名に変更してください。

## E2E テスト

```bash
npm run e2e
```

偽の SSD と偽の Osmo Action (2日 × 150 ファイル) をサンドボックスに作り、本番と同じ経路 (`startJob` → `assets/worker.js` → `rsync`) で転送して検証します。
起動元プロセスを強制終了しても転送が完了すること、中止、二重起動の拒否、同時起動の排他制御 (別プロセス / 同一プロセス × 8 の一斉起動)、異常終了の検出と再実行、容量不足の事前承認に加えて、設定ファイルの読み書きと検証、除外パターン、スキップ時の進捗・速度・残り時間、履歴の要約、プランの自動提案を確認します。
想定している失敗パターンは `e2e/FAILURE_MODES.md`、結果は `e2e/.out/report.md` に出力されます。
